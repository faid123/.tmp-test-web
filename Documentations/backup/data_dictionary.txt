--------------------------------------------------------------------------------
2. DETAILED ENTITY SPECIFICATIONS
--------------------------------------------------------------------------------

[User]
- Description: Represents application users, including clinical operators and admins.
- Fields:
    * uuid (PK)           : Unique identifier for the user.
    * username            : Unique login handle.
    * email               : Contact email address.
    * is_admin            : Boolean flag dictating administrative privileges.
- Relationships:
    * One-to-Many (1..*) with Role.
    * One-to-Many (1..*) with Alert (as sender or recipient).
    * One-to-Many (1..*) with Note (as sender/author).

[Case]
- Description: The core entity representing a patient case or clinical order.
- Fields:
    * id/caseIntID (PK)   : Internal unique integer primary key.
    * case_id             : Public or external case identifier reference (legacy String form -
                             caseIntID is the integer form used in most API envelopes and the
                             one encoded into shared QR/viewer links; the two are not interchangeable).
    * name                : Name designation for the case.
    * created_at          : Timestamp of case creation.
    * new_status          : Tracking status of the case lifecycle. Confirmed live enum values:
                             na, draft, 2d_design_pending, 2d_design_drafted, 2d_design_approved,
                             3d_design_pending, 3d_design_drafted, 3d_design_approved,
                             in_production, out_for_delivery, delivered, completed.
- Relationships:
    * One-to-Many (1..*) with Role, AdditionalCaseDetails, JawStruct, ClinicalInfo, STL, Thumbnail,
      CaseHistory, Note, Polyline, UndercutHeatmap, NoticeboardEditedView, and MailingList.

[Role]
- Description: Junction entity that maps users to specific cases with explicit access control permissions.
- Fields:
    * id (PK)             : Unique row identifier.
    * uuid (FK)           : Reference to User.uuid.
    * case_int_id (FK)    : Reference to Case.id.
    * role/permission     : Defined string or token specifying access level.

[AdditionalCaseDetails]
- Description: Case-list and dashboard workflow metadata, separate from the core Case record.
- Fields:
    * id (PK)             : Unique row identifier.
    * case_id/caseIntID (FK) : Reference to Case.id.
    * due_date            : Unix seconds timestamp.
    * new_status          : Workflow status (see Case.new_status enum above - drives the
                             case-list due-date colour indicator and dashboard progress display).
    * assigned_to         : Assigned user reference.
    * comments            : Free-text comments field (confirmed in caseManagement.js).
- Relationships:
    * Many-to-One with Case.

[JawStruct]
- Description: Holds structured Removable Partial Denture (RPD) CAD/CAM design data.
- Fields:
    * id (PK)             : Unique row identifier.
    * case_id (FK)        : Reference to Case.id.
    * type                : Categorization of upper_jaw or lower_jaw.
    * filename            : Source name of the saved configuration.
    * data                : Base64-encoded string containing structure data.

[ClinicalInfo]
- Description: Encapsulates specific clinical dental diagnostics and per-tooth metadata.
- Fields:
    * id (PK)             : Unique row identifier.
    * case_id (FK)        : Reference to Case.id.
    * data                : BinaryFormatter-serialized Base64 payload containing flags for teeth (e.g., mobility, rct, restoration, crown, implant, rootStump, cracked, tilted, extraction, abutment).

[STL]
- Description: Storage records for 3D jaw geometry model files, including the primary upper/lower
  jaw meshes and up to 4 extra reference slots.
- Fields:
    * id (PK)             : Unique row identifier.
    * case_id (FK)        : Reference to Case.id.
    * type                : Model taxonomy identifier.
    * filename            : Target mesh filename.
    * data                : Mesh file contents stored either as Base64 text or file reference paths.
    * slotNumber (extra slots only) : Integer 1-4 addressing an additional reference STL upload
      on the same case; not backed by a separate table. The backend carries no semantic meaning
      for the slot number itself - the upper jaw / upper metal RPD / lower jaw / lower metal RPD
      labeling is a frontend-only convention (EXTRA_STL_SLOT_NAMES). A future client assuming a
      different slot-to-label mapping could misfile a file under the wrong slot without error.

[Thumbnail]
- Description: Screenshot/preview images captured per case, distinct from raw STL/OFF geometry.
- Fields:
    * id (PK)             : Unique row identifier.
    * case_id (FK)        : Reference to Case.id.
    * slot/type           : Capture slot identifier (e.g. 2D, upper jaw, lower jaw).
    * data                : Base64-encoded image data.

[CaseHistory]
- Description: Backs the Version History feature - read by both the standalone
  VersionHistory.html page and the in-context modal, which are expected to show consistent data.
- Fields:
    * id (PK)             : Unique row identifier.
    * case_id (FK)        : Reference to Case.id.
    * action/status       : Recorded action or status transition.
    * created_at          : Timestamp of the history entry.

[Polyline]
- Description: Set of 3D coordinates representing path overlays drawn on the model geometry.
- Fields:
    * id (PK)             : Unique row identifier.
    * case_id (FK)        : Reference to Case.id.
    * jaw/type/component  : Contextual mapping indicating which jaw/part the line belongs to.
    * points/data         : Array or serialized representation of 3D spatial points.

[Note]
- Description: Direct communicative chat logs associated with individual cases.
- Fields:
    * id (PK)             : Unique row identifier.
    * case_id (FK)        : Reference to Case.id.
    * sender_uuid (FK)    : Reference to User.uuid.
    * message             : Text body content of the note.
    * image_data          : Optional Base64 attachment for diagnostic images.
    * created_at          : Creation timestamp.

[Alert]
- Description: Internal application notifications notifying actors of status updates or messages.
- Fields:
    * id (PK)             : Unique row identifier.
    * to_user_uuid (FK)   : Reference to target User.uuid.
    * from_user_uuid (FK) : Reference to originating User.uuid.
    * caseIntID (FK)      : Reference to Case.id.
    * read_status         : Tracking flag for notification status (read/unread).
    * message             : Informational notification text snippet.

[UndercutHeatmap]
- Description: Backs the undercut/occlusion analysis heatmap modes in the 2D-embedded and
  standalone 3D previews.
- Fields:
    * id (PK)             : Unique row identifier.
    * case_id (FK)        : Reference to Case.id.
    * jaw/type            : Which jaw/analysis mode the data applies to.
    * data                : Heatmap payload.

[NoticeboardEditedView]
- Description: Backs the 2D-to-desktop noticeboard report handoff (noticeboard.js). Three
  endpoint variants exist server-side, but only two are live in the web client:
    * "editedview" is the source of truth, written by this client.
    * "view" is a best-effort mirror of the same {case_id, filenames, data} payload, written
      so desktop's 2D/3D tabs (which only read "view") can see slides.
    * "drawnview" is referenced in a code comment as a legacy paint-overlay layer but has zero
      call sites anywhere in the web client - it should be treated as unimplemented here, not
      as a fourth live data source.
- Fields:
    * id (PK)             : Unique row identifier.
    * case_id (FK)        : Reference to Case.id.
    * filenames           : jagged byte[][] under .NET BinaryFormatter (MS-NRBF) framing -
                             a distinct shape from ClinicalInfo's per-string BinaryFormatter envelope.
    * data                : Raw PNG bytes.

[ArtificialTeeth (ToothCraftData)]
- Description: Artificial-teeth placement and geometry data, distinct from the polyline and
  jaw-mesh endpoints. Not a flat per-tooth table - a per-case, per-jaw pair of Unity
  MessagePack-encoded structs (toothCraftDataUpperJaw_ / toothCraftDataLowerJaw_), mirroring
  the Unity-side StageDataManager/ToothCraftData structure.
- Fields (per jaw, numeric-keyed sub-maps):
    * toothData_                          : Current tooth placement.
    * toothSurfaceMeshData_               : Current tooth geometry.
    * toothLandmarkInterfaceData_         : Current landmark data.
    * toothTransformInterfaceData_        : Current transform data.
    * initialToothSurfaceMeshData_        : Initial-state geometry.
    * initialToothLandmarkInterfaceData_  : Initial-state landmark data.
    * initialToothTransformInterfaceData_ : Initial-state transform data.
- Relationships:
    * Fetched via /toothPlacementData/get keyed by caseIntID as a fetch parameter - the
      case/jaw association is not a field inside the decoded blob itself.
    * Core rule: geometry source and placement source must match (each rendered tooth mesh
      tags its own geometrySource/placementSource for downstream diagnostics); mixing
      surfaceMesh geometry with toothData-only placement misaligns the tooth.

[MailingList]
- Description: Ad-hoc invite-by-email capture (POST /mailinglist/add), separate from the
  Role-based invite/access mechanism - no User or Role object is attached.
- Fields:
    * case_int_id (FK)    : Reference to Case.id.
    * email               : Invited email address (raw string, not a User reference).
