Diagnosis

The server's smart.updateSTL handler never binds case_id into the REPLACE INTO jaw_stls statement. The SQL is built with type, filename, data read from the request, but case_id is left unbound (NULL), violating the NOT NULL constraint on that column.

Existing rows stored via POST /stl have case_id = 2275 (integer, equal to caseIntID). The PUT handler should either populate case_id from the request body or look it up from caseIntID. Currently it does neither.

Web client impact

updateJawStl in src/js/2D/preview3D.js (line 422) calls PUT /stl with this exact payload shape. It will fail HTTP 500 against the live API until the server-side handler is fixed.

Recommendation

  • Fix smart.updateSTL to bind case_id in the REPLACE INTO statement (mirror POST /stl's handler).
  • Workaround: use POST /stl from updateJawStl until PUT is fixed — the REPLACE INTO on (case_id, type) already gives upsert semantics.
